## Décisions prises

- seo-geo = skills Claude Code, pas d'application ni d'espace client ; contenu validé = commit dans le repo du client (sites codés par Melvin)
- Un AI Overview dont les sources ne sont pas chargées compte « inconnu », pas « non cité »
- Migration SQL provenance à passer impérativement avant le déploiement Esprit Docker, sinon aucune commande enregistrée ; point CNIL (consentement pour le stockage de provenance) à trancher avant déploiement
- Maquettes prospect : toujours sur un sous-domaine de blue-impakt.org (`<prospect>.maquettes.blue-impakt.org`, CNAME générique, DNS only) plutôt que `vercel.app`, pour éviter le filtrage anti-spam ; plus rien à faire chez Cloudflare pour les prochaines, seulement `publication.domaine` dans la config d'envoi
- Volumes DataForSEO : si la tranche 1 échoue sur le réseau, on continue les SERP ; dès qu'une tranche payée existe, on enregistre le partiel et on s'arrête
- Esprit Docker : question du consentement CNIL pour le stockage de provenance remontée par la revue finale, à trancher par Melvin avant déploiement
- Boîte témoin de délivrabilité (Outlook.com / GMX) : ne jamais l'échauffer avec l'adresse testée, ni ajouter l'expéditeur aux contacts, sinon le test est faussé
- Mailing de prospection : montée progressive du volume d'envoi (10-20/jour puis 30-50) plutôt que rafale, pour protéger la réputation de blue-impakt.org, aussi utilisée pour les clients
- seo-geo, test pilote : Melvin a laissé la main (« prends décision seul ») ; décisions consignées dans `clients/esprit-docker/decisions-pilote.md`
- Esprit Docker : provenance des ventes = agrégat anonyme (option B) plutôt que consentement, pour rester dans l'exemption CNIL et mesurer tous les visiteurs
- seo-geo : mesure GEO sur Sonnet 5.5 (citations équivalentes à Opus pour moitié prix), recherche web classique et non « dynamique »
- Mails de prospection : pas de promesse chiffrée non prouvée (« augmente considérablement vos ventes ») ; dire comment le site apporte des demandes
