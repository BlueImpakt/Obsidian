# 17.05 Setup de Git et Github

## Resume
- Sommaire du module setup de Git et GitHub : introduction, comprendre Git, commits et branches, présentation de GitHub, installation de Git, configuration GitHub CLI.
- Anecdote nostalgique sur la gestion de versions pré-cloud (fichiers nommés « version 1 », « version 2 » manuellement échangés entre collègues), illustrant le problème résolu par Git aujourd'hui.
- Présentation de la fonction centrale de Git : pouvoir revenir en arrière en cas d'erreur ou de mauvaise direction prise dans le développement, un filet de sécurité indispensable.
- Explication de l'intérêt croissant de GitHub avec le nombre de développeurs sur un projet : stockage en ligne, récupération de la version la plus récente, création de branches et suivi collaboratif.
- Démonstration d'installation de Git via des gestionnaires de packages comme Winget (Windows) ou Homebrew, simplifiant l'installation de l'outil sur différents systèmes d'exploitation.
- Démonstration d'authentification GitHub via passkey pour autoriser un nouvel appareil, une méthode sécurisée alternative aux mots de passe traditionnels.
- Démonstration de configuration globale de Git (git config --global user.name) pour définir son nom d'utilisateur associé aux commits, une étape de configuration initiale essentielle.
- Précision sur les cas d'usage justifiant un IDE : accès fréquent aux fichiers, notamment pour du travail basé sur une base documentaire, un critère pour décider d'installer un IDE ou non.
- Présentation de la commande git pull, qui récupère la dernière version des modifications effectuées sur GitHub (remote) vers la machine locale, l'inverse du push.
- Présentation des commandes Git courantes de suivi : HEAD (pointeur vers le dernier commit), git status (état), git log (historique), git diff (différences entre fichiers).
- Explication de la symbiose entre Vercel et Next.js (même créateur) : dès qu'un push est effectué sur GitHub en production, Vercel déclenche automatiquement un build de déploiement de l'application.
